# Функции бота

## Команды

| Команда | Описание |
|---|---|
| `/start` | Приветствие и главное меню |
| `/menu` | Показать главное меню в любой момент |
| `/help` | Справка: команды, формат даты, флоу работы |
| `/cancel` | Отменить текущий ввод в любой wizard-сцене |

Все сообщения от не-администратора игнорируются молча (без ответа).

---

## Главное меню

После `/start` или `/menu` бот показывает кнопки:

```
[ 🖥 Открыть панель ]   ← webApp-кнопка Mini App (если задан WEBAPP_URL)
[ 👥 Клиенты   ]
[ 📊 Информация ]
[ ⚙️ Расписание ]
```

## Управление клиентами

### Список клиентов

**Вход:** кнопка «👥 Клиенты»  
**Отображение:** каждый клиент — отдельная кнопка. VIP-клиенты отображаются со звездой: `⭐ Иван Петров`.  
Внизу кнопки «➕ Добавить клиента» и «← Главное меню».

---

### Карточка клиента

```
👤 Иван Петров

Стоимость: 300 ₽
Подписка: ✅ активна до 30.05.2026

[ 📋 Подписки ]  [ ✏️ Переименовать ]
[ 💰 Изменить стоимость ]
[ ⭐ Сделать VIP ]
[ 🗑 Удалить ]   [ ← Назад ]
```

**Статусы подписки:**
- `✅ активна до ДД.ММ.ГГГГ` — есть активная подписка
- `❌ истекла ДД.ММ.ГГГГ` — подписка была, но закончилась
- `⬜ нет подписки` — подписок никогда не было

**VIP-кнопка** переключает статус:
- Нет VIP → `⭐ Сделать VIP`
- Уже VIP → `✖ Убрать VIP` (карточка показывает `👤 ⭐ Иван Петров`)

---

### Создать клиента

**Вход:** кнопка «➕ Добавить клиента»  
**Сценарий (Wizard, 3 шага):**
1. Бот: «Введите имя клиента:»
2. Администратор вводит имя → проверка уникальности
3. Бот: «Введите стоимость (целое число):»
4. Администратор вводит число → клиент создан

---

### Переименовать клиента

**Вход:** кнопка «✏️ Переименовать» в карточке  
**Сценарий (Wizard):** аналогично созданию, но обновляет только имя.

---

### Изменить стоимость

**Вход:** кнопка «💰 Изменить стоимость» в карточке  
**Сценарий (Wizard):**
1. Бот показывает текущую стоимость и просит новую
2. Администратор вводит целое неотрицательное число → обновлено

---

### Удалить клиента

**Вход:** кнопка «🗑 Удалить» в карточке  
**Сценарий:**
1. Бот: «Удалить "Иван Петров" и все его подписки?»  
   `[ ✅ Подтвердить ]  [ ❌ Отмена ]`
2. Подтверждение → каскадное удаление клиента и всех его подписок

---

## Управление подписками

### Список подписок клиента

**Вход:** кнопка «📋 Подписки» в карточке клиента  
**Отображение:** каждая подписка — кнопка с датами и статусом.

---

### Меню подписки

```
📋 01.04.2026 — 30.04.2026
✅ активна

[ 🔄 Продлить ]  [ ✏️ Изменить дату ]
[ 🗑 Удалить   ]
[ ← Назад ]
```

---

### Добавить подписку

**Если активной подписки нет** → выбор срока (пресеты или своя дата).

**Если активная подписка уже есть** → бот переходит в режим продления:
```
🔄 Продление подписки — Иван Петров

⚠️ Активная подписка до 30.05.2026.
Продление начнётся с этой даты.
```
Это исключает потерю оплаченного времени.

---

### Продлить подписку

**Ключевое правило:** `newEndDate = существующий endDate + срок` — платные периоды не теряются.

---

### Изменить дату подписки

**Вход:** кнопка «✏️ Изменить дату» в меню подписки  
Wizard: ввод новой даты в формате ДД.ММ.ГГГГ → валидация → обновление.

---

### Удалить подписку

Подтверждение → удаление → возврат в список подписок.

---

## Варианты срока подписки

| Кнопка | Поведение |
|---|---|
| 1 месяц | +1 календарный месяц от endDate |
| 3 месяца | +3 календарных месяца от endDate |
| 6 месяцев | +6 календарных месяцев от endDate |
| 1 год | +12 календарных месяцев от endDate |
| Своя дата | Ввод ДД.ММ.ГГГГ вручную |

## VIP-клиенты

VIP-статус предназначен для клиентов с автоматической оплатой.

**Что даёт VIP:**
- В списке клиентов и разделе «Информация» отображается ⭐
- Клиент **исключается** из уведомлений об истечении подписки
- При истечении подписки бот **автоматически продлевает** её на тот же период и уведомляет администратора

**Автопродление:** срок нового периода = `endDate − startDate` последней подписки. Отсчёт от старого `endDate` — дни не теряются.

**Формат уведомления об автопродлении:**
```
🔄 Автопродлено (VIP):
• Иван Петров — до 26.05.2026
```

---

## Расписание уведомлений

**Вход:** кнопка «⚙️ Расписание» в главном меню

**Изменение (Wizard):**
1. Бот показывает текущее cron-выражение
2. Администратор вводит новое (5 полей: `минута час день месяц день_недели`)
3. Валидация → сохранение в БД → применяется немедленно

**Примеры:**

| Выражение | Когда |
|---|---|
| `0 9 * * *` | Ежедневно в 09:00 (по умолчанию) |
| `0 8 * * 1-5` | В 08:00 только по будням |
| `0 9,18 * * *` | В 09:00 и 18:00 |

> Время — по часовому поясу сервера. UTC+3 (МСК) = вычти 3 часа: `0 6 * * *` = 09:00 МСК.

---

## Ежедневные уведомления

```
🔄 Автопродлено (VIP):
• Иван Петров — до 26.05.2026

⚠️ Подписка истекает СЕГОДНЯ:
• Мария Иванова (до 26.04.2026)

🔔 Подписка истекает ЗАВТРА:
• Алексей Сидоров (до 27.04.2026)
```

VIP-клиенты в блоках ⚠️ и 🔔 **не появляются** — только в блоке 🔄.

## Обработка ошибок

| Ситуация | Поведение бота |
|---|---|
| Сообщение от не-администратора | Игнорируется (нет ответа) |
| Некорректный формат даты | Повторный запрос с подсказкой формата |
| Дата в прошлом | Повторный запрос с объяснением |
| Дублирующееся имя клиента | Повторный запрос с указанием на дубль |
| Отрицательная или нечисловая стоимость | Повторный запрос с примером |
| Невалидное cron-выражение | Повторный запрос с примером |

## Mini App: панель 3x-ui

Открывается кнопкой «🖥 Открыть панель». Доступ только у администратора
(HMAC-проверка Telegram initData + сверка с `ADMIN_TELEGRAM_ID`).

### Вкладки

| Вкладка | Содержимое |
|---|---|
| 📊 Обзор | CPU/RAM/диск (прогресс-бары), сеть ↑↓, статус и версия xray, онлайн-счётчик, число инбаундов, баннер обновления; поллинг 10 с; шестерёнка — состояние сессии панели, переподключение, логаут |
| 🔀 Инбаунды | Список (протокол, порт, трафик, число клиентов) → деталка (кнопки действий сверху: изменить / удалить / сбросить трафик; аккордеон клиентов снизу) → структурная форма (remark, порт, протокол; транспорт tcp/ws/grpc/xhttp; безопасность none/tls/reality с генерацией ключей; экзотические протоколы и нераспознанный конфиг — JSON-режим) |
| 👥 Клиенты | Постраничный список с поиском (debounce), фильтрами (все/онлайн/включённые/истёкшие) и онлайн-бейджами (поллинг 15 с); bulk-режим: «+30 дней выбранным», чистка истёкших/сирот |
| 🖥 Сервер | Статус (поллинг 5 с), sparkline CPU/RAM, рестарт/стоп xray, рестарт панели, обновление панели, установка версии xray, логи (панель/xray, 50/100/500 строк) |

### Карточка клиента панели

- Прогресс трафика (израсходовано из лимита), срок или «Бессрочно», last seen, лимит устройств.
- **Ссылки подключения**: tap-to-copy и QR-код (генерируется локально).
- IP-лог (сворачиваемый) с очисткой.
- Привязка к клиенту бота (bottom-sheet), отвязка, изменение, сброс трафика, удаление.

### Форма инбаунда

Для протоколов `vless`, `vmess`, `trojan`, `shadowsocks` форма разбита на смысловые
блоки вместо одного JSON: транспорт (`tcp`/`ws`/`grpc`/`xhttp`) и безопасность
(`none`/`tls`/`reality`) — отдельными полями, `settings`/`streamSettings` собираются автоматически.

`wireguard` имеет отдельную форму: секретный ключ (с генерацией), MTU, пиры; транспорт и безопасность не применимы.

Для reality (приватный/публичный ключ) есть кнопка «🔑 Сгенерировать ключи», для wireguard —
«🔑 Сгенерировать ключ» — оба используют эндпоинт `GET /api/server/new-x25519` (прокси `getNewX25519Cert`
панели, ответ `{ privateKey, publicKey }`).

Экзотические протоколы (`dokodemo-door`, `socks`, `http`), а также конфиг, который парсер не
распознал при редактировании существующего инбаунда, переключают форму в JSON-режим —
`settings`/`streamSettings`/`sniffing` редактируются как текст напрямую.

### Привязка клиентов (экран 🔗)

Список клиентов бота (имя, VIP, срок подписки) со статусом привязки. Привязка через
пикер email панели с поиском; email проверяется в панели; повторная привязка того же
email к другому клиенту → ошибка 409. При удалении клиента панели привязка чистится
автоматически.

### Карточка клиента в боте

Если клиент привязан (`xuiEmail`), карточка показывает живые данные панели:
трафик ↑↓ и last seen. При недоступной панели — «Панель (…): ⚠️ недоступна»,
бот продолжает работать.

### После рестарта/обновления панели

Mini App показывает оверлей «Панель перезапускается…» и поллит `/api/session`
до восстановления; разрыв соединения после POST трактуется как успех.

### api()-клиент webapp

3x-ui на части мутаций отвечает при успешном ответе (res.ok) с пустым телом; обёртка `api()`
читает тело через `res.text()` и возвращает `undefined`, если оно пустое, вместо вызова
`res.json()` — это убирает ошибку `Unexpected end of JSON input` на успешных ответах
без содержимого.
