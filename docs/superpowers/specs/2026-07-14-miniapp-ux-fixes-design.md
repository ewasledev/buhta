# Mini App: UX-доработки и багфиксы — дизайн

Дата: 2026-07-14. Статус: утверждено.

Пять доработок Telegram Mini App (webapp/ + src/webapi, src/xui). Порядок реализации: 5 → 1 → 3 → 2 → 4 (от дешёвого к дорогому).

## 1. Баг: пустой экран при запуске

**Причина.** Telegram Desktop/Web открывает Mini App с хэшем `#tgWebAppData=...&tgWebAppVersion=...`. `HashRouter` трактует его как путь; ни один `<Route>` не совпадает — рендерится пустой экран, пока пользователь не тапнет таб.

**Решение.** Catch-all роут в `webapp/src/App.tsx`:

```tsx
<Route path="*" element={<Navigate to="/" replace />} />
```

`initSdk()` вызывается в `main.tsx` до рендера React, initData к этому моменту уже прочитана SDK — затирание хэша безопасно. Заодно чинит любые битые диплинки.

## 4. Структурная форма инбаунда

Переделка `webapp/src/screens/inbounds/InboundForm.tsx` из трёх JSON-textarea в типизированную форму. Охват: частые сценарии, экзотика — через JSON.

**Секции формы:**

- **Основное** (как сейчас): название (remark), порт, протокол, включён.
- **Транспорт** (для vless/vmess/trojan/shadowsocks): селект `tcp / ws / grpc / xhttp`; по типу:
  - ws, xhttp — path, host;
  - grpc — serviceName;
  - tcp — без доп. полей.
- **Безопасность:** селект `none / tls / reality`:
  - reality — dest, serverNames, shortIds (автогенерация), privateKey/publicKey + кнопка «Сгенерировать ключи» (X25519 через эндпоинт панели);
  - tls — пути к сертификату/ключу.
- **Протокольные поля:**
  - vless — flow (для TCP+reality), decryption фиксирован `none`;
  - shadowsocks — метод шифрования (селект) и пароль с автогенерацией;
  - vmess, trojan — минимум (клиенты добавляются отдельно);
  - wireguard — секретный ключ с генерацией, mtu, пиры (publicKey + allowedIPs); транспорт/безопасность не применимы.
- **«Дополнительно (JSON)»** остаётся: показывает собранные `settings`/`streamSettings`/`sniffing`; для dokodemo-door/socks/http — форма сообщает, что протокол настраивается только через JSON, и показывает textarea (текущее поведение).

**Логика:**

- Форма — источник истины; JSON-поля собираются на сабмите чистыми функциями (`buildSettings`, `buildStreamSettings`).
- Редактирование: существующий JSON парсится в поля формы (`parseInbound`); нераспознанная структура → JSON-режим с пометкой, без потери данных.
- Бэкенд: если у 3x-ui нет проксированного эндпоинта генерации X25519 (сверить с `docs/openapi.json`) — добавить метод в `XuiService` и роут в `inbounds.controller.ts`.

## 5. Критикал-баг: «Unexpected end of JSON input» при создании клиента

**Причина.** 3x-ui на `clients/add` возвращает `obj: null` → NestJS отдаёт `201` с пустым телом → `api()` в `webapp/src/api/client.ts` безусловно зовёт `res.json()` и бросает исключение. Клиент при этом реально создаётся.

**Решение.** В `api()` успешный ответ читать через `res.text()`: пустая строка → `undefined`, иначе `JSON.parse`. Одна точка — чинит все мутации с пустым телом (delete, reset-traffic, attach/detach и др.).

## Тестирование

- vitest: `api()` — пустое тело, валидный JSON, ошибка с JSON-телом и без;
- vitest: `buildSettings` / `buildStreamSettings` / `parseInbound` — по протоколам и транспортам, включая round-trip (parse → build);
- остальное — смоук в Telegram (запуск с чистого старта, экран инбаунда, создание клиента и инбаунда).
